# Durable sandbox foundation (issue #59, child of #37)

This is the durable server-side foundation slice only: exact owned Python-artifact proposal → exact approval → separately funded, fenced execution journal → bounded Markdown publication, exercised through the real SQL coordinator and a bounded gateway client against an offline scripted wire endpoint. It does NOT close #37's vendor/isolation/live acceptance and enables no execution.

## What exists

- `lib/sandbox/contract.ts` — the exact binding schema: owned artifact revision plus content SHA-256, provably empty selected-input digest list, immutable image/interpreter digests, provider/account/region, the unchanged policy ceilings (1 owner / 2 global active including uncertain orphans, 1 vCPU, 512 MiB RAM, 128 MiB disk, network denied, package installation denied, 5-minute absolute lifetime, command ≤15 s inside the original 20-second lease, 5 attempts / 10-minute job wall, no deadline renewal), gateway protocol/key identity, fee/envelope/plan/capacity digests, exact action revision `sandbox-python-run-v1` and approval expiry. Wire result and logs are ≤4 KiB; the published artifact and the input are ≤128 KiB.
- `lib/sandbox/config.ts` — the provider boundary. The catalog admits nothing: `cloudflare-containers-v1` denies with `sandbox_cost_baseline_unmet` ($5 platform baseline), `sandbox_disk_minimum_exceeded` (2 GiB minimum versus 128 MiB) and `sandbox_lifetime_guarantee_missing` (inactivity shutdown is not an absolute five-minute lifetime); `modal-v1` denies with `sandbox_isolation_unproven` and `sandbox_disk_cost_enforcement_unproven`; unknown ids deny with `sandbox_provider_unknown`. The only constructible adapter, `offline-scripted-v1`, is private and test-only: every privileged call re-evaluates the provider decision and rejects it outside `NODE_ENV=test`. The synthetic offline fee snapshot is labeled `synthetic-offline`, covers worst-case startup, compute, disk, egress, logging, orphan retention, cleanup and fees, and is never vendor pricing.
- `lib/sandbox/gateway-client.ts` — the bounded wire client: fixed paths, fixed protocol header, no redirects, a hard 4 KiB response cap, digest-only requests (never source content), path-safe handle validation, and explicit outcome classes: definitive rejection (terminal transport evidence) versus ambiguous (timeout, connection loss, oversized or malformed response — remote existence stays unknown).
- `lib/sandbox/store.ts` — the durable journal. Funding happens BEFORE entry under the funding lock, then the established byok → attachments → jobs → owner lock order, with fresh authoritative SQL/config/clock checks after every await and write. The operation reserve, entry and the durable creation tombstone (`create_requested_at`) commit in one transaction before any create call. Recovery paths reconcile/status/terminate only the same operation and never create again; definitive create rejection releases at zero with retained evidence; anything ambiguous retains full liability, records terminal transport evidence and stops all funded admissions. Publication and job completion share one transaction guarded by the current fence, lease, approval and source identity, using `mutateArtifactInTransaction`; any loss rolls back all new rows. Status/terminate are zero-create.
- `lib/db/sandbox-schema.ts` + `drizzle/0022_sandbox_execution.sql` — the journal schema. Financial operation, evidence, audit, commitment, period, receipt, retained-principal and counter-key rows are anonymous (actor-key only), never reference owners by cascade and are append-only or transition-guarded by SQL triggers; owner/job/source payload metadata lives in a separate `sandbox_operation_owner` map that cascades. The retained principal pins the canonical numeric GitHub account identity under a domain-separated secret, so account recreation or actor-key rotation never resets limits; legacy financial actors are untouched. 0022 additively extends `durable_job` with the sandbox action revision and its precise error codes; old migrations are untouched and the 0021→0022 population-preservation test proves it.
- `lib/funding/store.ts` — `checkUncoveredSandboxExposure` (a missing or increased prior-month namespaced carry blocks ALL funded admission), `sandboxCommittedInTx` and `assertSandboxEnvelopeInTx` (`ordinaryInfra + sandboxCommitted + incoming ≤ k_infra`, against the existing plan only; Acredit and Amcp are never borrowed and the global arithmetic `Acredit + Amcp + Kinfra + Kfees + Ksafety + Lcarried ≤ B ≤ $10` is untouched). The reviewed ordinary-infrastructure commitment is bootstrapped per month in `sandbox_period` — zero ordinary infra is never assumed.
- `lib/jobs/{contract,store}.ts` — minimal internal action/fence helpers (`jobInternals`, `registerJobActionHandler`); fixture job behavior and the #52 API/UI are unchanged.
- `lib/sandbox/coordinator.ts` — the test-only coordinator that binds a store to a gateway client for the durable jobs action registry. Nothing registers it in production; `lib/jobs/worker.ts` keeps its `NODE_ENV=test` gate.

## Offline proof

`tests/sandbox-foundation.integration.test.ts` runs against real SQL (PGlite) and a real local HTTP endpoint (`tests/helpers/sandbox-gateway-fixture.ts`) that implements durable creation tombstones and scripted outputs only — no supplied code is ever executed or interpreted. It distinguishes offline wire behavior from real vendor enforcement and covers: 0021→0022 migration preservation; ownership/source/approval/policy/funding drift with zero creation calls and no consumed approval or reservation; the envelope arithmetic; missing/increased prior-month carry blocking all funded admission until the namespaced carry is bootstrapped; frozen carry immutability; exactly-once creation across crash, response-loss and lease-expiry boundaries; recovery publishing with the fresh fence without a second create; cancellation and stale fences; retained liability with funding stop; orphan holds counting against owner/global active capacity; recreated accounts and rotated keys keeping the retained principal; zero-create status/terminate; oversized, malformed and path-crafted wire handling; and sanitized account exports (no handles, identities or fee snapshots).

## Remaining gates (explicit, not claimed)

- Vendor: no provider account, pricing review, minimums/egress/deletion terms or isolation evidence exists. Cloudflare's $5 baseline, 2 GiB disk minimum and missing absolute-lifetime guarantee, and Modal's unproven disk/cost enforcement, deny every production path.
- Native: real concurrent-backend contention for the funding/jobs lock ordering and physical snapshot restore remain native PostgreSQL gates (PGlite is single-connection).
- Hosted: no worker/queue activation, no deployment, no application-host execution, no billing enablement, no real provider calls. Unknown-outcome liability, authentic settlement and remote stop/refund semantics require live vendor evidence before any of this can be considered.
