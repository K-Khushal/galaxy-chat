# Durable, resumable Generations backed by Upstash Redis

A Reply must survive the User losing connection, refreshing or switching devices without restarting the model request or losing output. So a Generation runs on the server independently of the HTTP connection (Next.js `after()` plus `consumeStream`). The Chat records which Generation is active, and `resumable-stream` lets any client that reconnects replay and follow it. That package keeps the chunks in the producing function's memory and uses Upstash Redis only for coordination and pub/sub, so replay works while the Generation is alive. Once it has finished or its function has died, the Reply is read from Postgres. The partial Reply is also saved to Postgres every few seconds, so output outlives the function. A Generation whose function dies cannot be continued from the same provider request; it ends as Interrupted with its last checkpoint. Closing a tab therefore never stops a Generation; Stop is an explicit server-side signal sent through Redis. The per-Chat Generation lock lives in Redis with an expiry, never as a row in Postgres, because the inherited `chat_run` rows stuck in `pending` locked Chats permanently. Temporary chats are deliberately not resumable. Redis also holds OTP and verification state, rate limits and cached model metadata.

## Consequences

- A Generation's length is capped by the Vercel function time limit (about 300s on Hobby, up to 800s on Pro). A Generation that hits the cap ends as an Interrupted Reply that can be continued.
