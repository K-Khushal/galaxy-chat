## Guest integration and safety

`/guest` is a public, basic text-only exchange against `/api/guest`; it never calls private chat/credits/provider/history APIs. It displays checking, unavailable, bot-required, ready, busy, shared-exhausted, streaming, stopped, used and error states. The server decides availability. A failed availability read disables generation. Unconfigured checked-in environment values show unavailable, never a fabricated response or invitation. The only continuation is the existing `/sign-in` route; sign-in does not save/transfer a guest exchange or grant a beta invitation.

GET exposes coarse state, remaining generation and safe limitations/reason IDs. A validated nonsecret `GUEST_TURNSTILE_SITE_KEY` is returned only while available. `guestConfig` requires the valid key for both GET and POST, along with the pre-existing real server bot secret, HTTPS origin and explicit trusted Cloudflare-only-origin assertions. Direct POST with a valid signed cookie and otherwise-valid fixture proof still rejects missing/blank/malformed site keys before bot verification, attempts, reservation or provider entry. No global budget amount, provider key, cookie secret or server bot secret enters public configuration.

The client uses the installed AI SDK `DefaultChatTransport` with an explicit strict `{requestId,text,botToken}` request body and `readUIMessageStream`, no chat history/resume, retries or advanced controls. It uses the real provider SSE stream, requires a valid terminal finish, preserves partial text and gives stable, redacted error messages. A same-tick pending ref prevents duplicate submit; no failed request is automatically replayed. Stop and unmount abort the browser request; the guest handler now forwards `request.signal` into funded execution. An entered Stop retains its unknown hold and consumed guest allowance. Input displays the same 2,000-byte JSON-encoded text bound enforced by `boundContext`, including Unicode/escaping overhead. A 32,000-character total text guard aborts before accumulating excessive UI text; provider output remains bounded to 512 tokens on the server.

Guest output renders as React-escaped plain text, so Markdown links, image syntax, raw HTML and JavaScript URLs are inert and do not load remote content. It does not expose model/key/billing/file/tool/search controls. The shared signed-in Streamdown renderer additionally has a real-render regression against script tags, event handlers, script-protocol links and iframes. These are renderer tests, not claims of browser XSS coverage.

The real Turnstile script is loaded only with server-available state and a valid public site key. It uses the official explicit-render script and `ready`/`render`/`remove` lifecycle, fixed `galaxy_guest` action, flexible width, callback proof, expiry/error/timeout invalidation, stale-callback guard and removal on unmount. Proof is cleared before sending and a fresh widget mounts after an explicit availability refresh. Script/challenge failure disables Send and offers a new check. No Turnstile script or external request occurs in local fixtures. Actual widget provisioning, trusted edge, single-use/expiry behavior and physical devices still require live acceptance.

`/preview/ui?guest=available|botpending|used|disabled|busy|exhausted|error|streaming` reuses the production component with an injected local client and visible fixture label. It exists only behind the existing development runtime plus `F04_UI_HARNESS=1` gate; it does not bypass `/chat` authentication. Available fixtures allow local send, stop and used-to-sign-in checks without auth, database, Turnstile or provider calls. The surface uses the existing semantic palette, Geist typography, Button primitive, 44px controls, visible focus tokens, native textarea, polite status/alert output, 16px mobile input and safe-area/dynamic-viewport layout. Streaming text and repeated chat actions do not animate; shared reduced-motion rules cover the small activity indicator. Root owns independent browser/client-performance/accessibility evidence; no screenshot, screen-reader, contrast or physical-device pass is claimed by this implementation slice.

## Local measurements and recovery

Final full-suite run measured guest request-to-first-text **11.38ms**, complete text stream **14.26ms**. This includes the local guest handler/SQL/installed SDK parsing with an immediate in-memory synthetic provider response; it excludes real model latency, network, hydration and rendering. It is not a hosted first-token SLO. The earlier full-suite run measured first text 10.36ms on a warmed process; isolated cold runs measured 34–43ms. The regression retains an explicit two-second local first-text bound.

A physical fake-data PGlite snapshot/restore measured **565.19ms**, snapshot **4,758,941 bytes** in the final full-suite run. It restores actual owned chat data, encrypted saved credentials, exact ledger charges, RLS, append-only trigger and foreign-key constraints. The original fixture is drained before the physical snapshot; the restored engine owns its own direct queue and has no competing socket. Ciphertext is inspected without printing key material, and separately supplied fixture keyring decrypts the restored record. The missing-owner insertion must fail with PostgreSQL `23503`. No cloud backup, production RPO/RTO, secret-manager recovery or deployed binary rollback is inferred from this proof.
