## Contract and integration

`drizzle/0007_artifacts.sql` is independent of reserved F09/F10 migrations 0005/0006. It creates owned artifact records and immutable revision rows. Composite foreign keys tie the artifact to the same owner's conversation and originating message; originating IDs, owner, kind and creation timestamp cannot be reassigned. The current revision must exist at transaction commit. Revision updates and individual revision deletion are rejected by database triggers. Explicit artifact deletion, originating conversation/message deletion, and account deletion cascade through all artifact revisions. Artifacts are user content; financial/resource audit records retain their existing retention rules.

`POST /api/artifacts` accepts strict action objects:

- `create`: `chatId`, `messageId`, `kind: markdown|html`, `title`. The server reads an actual owned persisted assistant message and copies its text as revision 1. Client-supplied content/owner fields are rejected. A whole-response matching Markdown/HTML code fence is unwrapped; otherwise the saved text is copied verbatim.
- `save`: `id`, `expectedVersion`, `title`, `content`. Adds a revision, with compare-and-swap conflict detection.
- `restore`: `id`, `expectedVersion`, `version`. Copies the selected historical title/source into a new revision with `restoredFrom`; it never overwrites the original.
- `delete`: `id`. Removes that artifact and all revisions.

`GET /api/artifacts?chatId=...` lists owned conversation artifacts. `?id=...` reads the current document and bounded revision metadata. `?id=...&download=source` downloads saved raw source as `text/plain`, `attachment`, `nosniff`, private/no-store, with a deny-all sandbox CSP. Filenames allow only ASCII letters, digits, underscores and hyphens, bounded to a 72-character stem. Markdown uses `.md`; HTML intentionally uses `.html.txt`, preventing automatic HTML execution on download/open. No “run”, external preview, server-code, MDX-import, tool, or model-call path is added.

All mutations use invited signed-session access and the existing same-origin/CSRF check. A real owner-row lock serializes creates, saves, restores and deletions, including quota accounting and version changes. Limits are fixed: 128 KiB UTF-8 source per revision, 40 immutable revisions per artifact, 50 artifacts per owner, 8 MiB total owned revision source. Metadata and request sizes are separately bounded (120-character title, 200-character identifiers, 800 KiB request stream before JSON parsing). Reaching the revision cap keeps reading/downloading/deleting available. Storage counts all revisions; deleting an artifact frees its source allowance.

`exportOwnedAccount` now includes `artifacts` and `artifactRevisions` filtered by session owner. The established user/chat/message cascades provide deletion; no financial/resource audit deletion was added. Existing key encryption/export exclusions and funding/BYOK boundaries remain intact.

`ChatMessages` exposes optional `artifactChatId`. The shared `Chat` shell now supplies it only for a confirmed persisted conversation with F09 `temporary` false. Confirmation comes from initial owned branch data, a successful durable branch response header, or an owned branch reload; the confirmed ID must match the current conversation ID. The same gate supplies `ConversationArtifacts({chatId})` in the conversation header for reopening documents. The message-level component receives `messageId` for explicit creation. Temporary client-only transcripts have no durable origin and server creation fails closed; the real signed-guest/temporary-stream regression verifies this. Artifact source is never automatically added to model context. The guest UI is unchanged. No new F11 inference-route behavior is added.

## Preview and editor boundary

The focused panel reuses the existing semantic colors, typography, Button/Input/Textarea and Radix-backed Sheet and Tabs. Tab arrow-key/selection semantics come from the existing Tabs primitive. All create/open/save/restore/delete actions retain their idle labels while pending, with `aria-busy`, spinners and duplicate-action guards, following `docs/system/button.md`. Initial list loading is disclosed and creation waits for the initial list read. Opening a document focuses its title; returning to the list/deleting focuses its heading; save/restore recover an appropriate editor control. Browser focus/scroll results remain pending. It offers title/source editing, a reading preview, history/restore, explicit all-revisions deletion confirmation, save status/errors and saved-source downloads. Duplicate local mutations are prevented with a same-tick pending ref. Unsaved source/title edits prevent sheet close, navigation back to the artifact list, restoration and browser unload until saved/discarded. Mobile inputs remain 16px, the panel uses dynamic viewport height, scroll containment and bottom safe-area padding. Existing sheet motion is disabled for reduced motion; repeated editing/view actions receive no new motion.

HTML is parsed using the existing installed HAST/parse5 stack and a deliberately narrow schema. Only document structure/text/basic semantic formatting survives. URL-bearing attributes, CSS/custom styles, event handlers, scripts, forms, inputs, metadata/base/refresh, frames/embeds, SVG/MathML and custom elements are removed. Links become inert text. CommonMark is parsed without MDX/JSX/module extensions, converted to HTML and passed through the same allowlist. A source byte guard and tree node/depth bounds constrain output. Parser recursion failures produce fixed inert fallback markup, never the unparsed source, and keep editing available.

The safe result is placed only in an iframe `srcDoc`, with `sandbox=""`, no `allow-scripts` and no `allow-same-origin`, and `referrerPolicy="no-referrer"`. A CSP appears before document content: default/script/connect/image/media/font/object/frame/worker sources are denied; base URLs and form actions are denied. Only the application's fixed inline reading stylesheet is permitted; source styles are stripped. The iframe therefore receives an opaque origin and no parent credential access. No `postMessage` bridge, blob origin, relaxed sandbox mode, navigation allowance, popup allowance or external-execution switch exists. The AST allowlist removes link/refresh/self-navigation vectors; the empty sandbox separately denies top navigation/popups/scripts/forms.

This follows the [HTML standard iframe sandbox model](https://html.spec.whatwg.org/multipage/iframe-embed-object.html) and [iframe isolation guidance](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe). CSP is defense in depth; the implementation does not rely on unsupported `navigate-to`, meta-delivered `sandbox`, or regex-only HTML filtering.
