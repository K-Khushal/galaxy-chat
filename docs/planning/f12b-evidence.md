## Contract, ownership and storage

Typed tables extend the existing F11 artifact store with a fourth immutable kind. `drizzle/0010_table_artifacts.sql` changes only the artifact kind check to `markdown|html|chart|table`; it preserves the existing owner/message foreign keys, revision and origin immutability triggers, RLS/browser-role revocations, byte accounting, cascades and quotas. Migration numbers 0008 and 0009 remain assigned to tools and charts.

`lib/artifacts/table-spec.ts` accepts only strict version 1 positional JSON. A table has a title, description, labeled columns, and labeled rows with exactly one value per column. Cells are text, a finite number or a boolean. `null`, arrays, objects, formula objects, non-finite numbers, unknown keys and ragged rows fail closed. Text remains data; no formula, HTML, MDX, expression, callback, URL-fetch or component field exists.

The parser measures UTF-8 before parsing and enforces 128 KiB source, 10,000 rows, 50 columns, 200,000 positional value slots including empty strings, and 4,096 Unicode scalar values per text cell. Accepted text is valid for the generated formats: cell text may contain tab, CR and LF, while invalid controls, lone surrogates and `FFFE`/`FFFF` code points fail validation. Titles and labels are bounded to 120 scalar values and descriptions to 1,000. Generated CSV and XLSX are independently rejected above 8 MiB. Tests cover the exact source, cell, row, column and slot limits; a library-owned generator seam exercises the signed owner-qualified route at exactly 8 MiB and one byte over after generation.

Create, save and restore dispatch through the existing kind validator and preserve compare-and-swap heads, 40 immutable revisions, the 50-artifact count, the shared 8 MiB owner source quota, account export, and account/chat deletion. Table creation still reads source from the owner's persisted assistant message. It accepts one complete JSON object or one whole-response `json`/`table` fence; callers cannot supply source or ownership directly.

CSV/XLSX export requires an explicit saved version from 1 through 40. `readArtifactRevision(userId, id, version)` is owner-qualified and returns the persisted kind and the revision's own title/content. There is no head fallback or client-supplied kind. The route reparses persisted source before generation, so malformed historical content cannot be downloaded or restored. Cross-owner reads return not found; unsigned and guest requests are denied. Integration proof saves a new head and then verifies that version 1 produces the same bytes as before the save.

## Safe export behavior

CSV output is UTF-8 with a BOM, quoted text, doubled embedded quotes, CRLF records and a final CRLF. Numbers remain unquoted canonical number text and booleans become `TRUE`/`FALSE`. Before quoting any untrusted string, including row and column labels, the exporter scans leading Unicode whitespace, controls and format characters. Text beginning effectively with `=`, `+`, `-`, `@` or the full-width equivalents gets a leading tab. Thus text `"-42"` is normalized while numeric `-42` remains a number. The original JSON revision is unchanged. An independent parser test round-trips commas, quotes, multiline text, emoji, Arabic text, empty text and the direct/hidden/full-width formula-prefix corpus.

XLSX output uses application-built `{t,v}` cell objects only: `s` for text and headers, `n` for finite numbers, and `b` for booleans. The server-only adapter makes one fixed-name `Table` sheet in memory and never sets formula/cache/link fields, workbook names, relationships, macros or external references. Structural tests reopen the ZIP with formula and VBA visibility, verify the typed cells and one worksheet, inspect every cell for absent `f`, `F` and `l`, and scan package XML/relationships for formulas, hyperlinks, external targets, external-link parts, VBA parts and macro-enabled workbook types. Formula-looking text, URLs, XML-like text, multiline astral Unicode and RTL controls remain plain text without replacement glyphs.

Both formats are generated only after the owner-qualified revision read and returned directly. No generated object or public/signed URL is created. A shared F10/F12-B header helper supplies a sanitized ASCII fallback plus RFC 5987 filename, exact length, private/no-store, nosniff, sandbox deny-all CSP and no-referrer. Filenames include the immutable revision, for example `typed-table-v1.csv`. Existing attachment response regressions remain green after extracting the helper.

SheetJS Community Edition `xlsx` 0.20.3 is vendored unmodified from the official CDN and installed through `file:vendor/sheetjs/xlsx-0.20.3.tgz`; the stale public-registry release was not used. The tarball is 2,409,319 bytes with SHA-256 `8dc73fc3b00203e72d176e85b50938627c7b086e607c682e8d3c22c02bb99fe8`. The extracted Apache-2.0 license is 11,355 bytes with SHA-256 `4d2a38ac35cda06a555c84074a819d413339cd3691b822cae50f8f322fe01f64`. `vendor/sheetjs/PROVENANCE.md` records the official source, version, hashes and license. The package has no runtime dependencies. The existing vendor-integrity command now checks both Halaska and SheetJS checksum manifests. A direct Bun spike and the installed package both wrote and reread typed, formula-looking values before product integration.

The XLSX adapter imports `server-only` and the artifact route reaches it through a dynamic server import only for `download=xlsx`. No SheetJS/version/exporter signature appears in the built browser chunks. The table preview and fixture contain no workbook library import.

## Preview and public copy

The workbench adds a typed-table creation option, strict source validation, invalid-save blocking, an accessible preview and revision-specific CSV/XLSX actions. Downloads always use the selected saved revision while the preview reflects current editor content. The native preview has a caption containing the title and description, column and row scopes, exact primitive values, explicit empty-text speech, wrapping, and a keyboard-focusable bounded scroll region. It renders 100 rows per page with previous/next controls and a polite `Rows X–Y of N` status so every bounded row remains reachable without creating a 200,000-cell DOM.

`/preview/tables` is available only under the existing development plus `F04_UI_HARNESS=1` gate. It uses the real workbench with in-memory immutable history, mixed primitives, multiline and Unicode text, long and formula-looking values, invalid recovery, save/restore/delete, selected revisions, and theme controls. Its download actions are deliberately disabled because production export requires an authenticated owned database revision and the SheetJS library must remain server-only. The shared preview width picker already includes 390 px.

Help explains the table schema, primitive types, selected-revision export, CSV normalization and unchanged source. It says this mitigation is not a universal cross-application guarantee and names Microsoft Excel, LibreOffice Calc, Apple Numbers and Google Sheets as pending compatibility checks. Privacy copy states that generated table files are ephemeral authenticated downloads and are not stored as new objects. Existing attachment, chart, funding and inference behavior remains in place; table editing/export makes no provider request or paid call.
